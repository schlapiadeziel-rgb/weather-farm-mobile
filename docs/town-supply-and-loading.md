# 小镇补货往返与首屏加载

基于 v0.28.0 和开发中的小镇看板改动继续优化，尚未生成或发布新 APK。没有修改游戏经济数值、存档格式或安卓版本号，真实农场助手维持独立数据。

## 补货后回到原访客

从访客卡片的缺货入口前往农田、牧场、蜂箱或工坊后，页面提供“返回某某访客”，并显示原店铺。返回会选择对应店铺、滚动并聚焦原访客，仍需玩家手动交付物品、接待和领取报酬。

加工品需要多层原料时，优先逐层返回原配方，配方路径返回完毕后再提供访客入口。例如：青松需要奶油蛋糕 → 查看奶油 → 去牧场补牛奶 → 返回奶油配方 → 返回奶油蛋糕配方 → 返回青松访客。

点击结束导航、主动切换到其他经营页面、进入真实农场助手或重新加载页面，会结束本次补货路径。从另一位访客重新发起补货时使用新来源。普通配方补货仍可逐层返回；查看和返回不扣货、不制作、不接待或发放报酬。访客已经离开时，返回停留在原店铺。

小镇与工坊的蜂蜜来源提示改为“蜂箱”，与实际前往的探索蜂箱页面一致。

## 页面按需加载

小镇、生产工坊和经营面板通过现有页面加载提示进入时读取。订单、仓库和探索共用经营面板模块。新农场先显示农田，不再预先加载这些页面的代码与独立样式；首次打开各页面后，再次进入复用已加载模块。

同一依赖锁定文件、同一构建环境中，对比优化前开发提交 `c901a0d` 与v0.29.0 最终网页构建：

| 首屏入口资源 | 优化前（字节） | 优化后（字节） | 减少 |
| --- | ---: | ---: | ---: |
| JavaScript | 723,013 | 630,601 | 12.78% |
| JavaScript gzip | 221,114 | 193,848 | 12.33% |
| CSS | 242,812 | 194,756 | 19.79% |
| CSS gzip | 48,965 | 39,748 | 18.82% |

gzip 使用 Python `gzip.compress(..., mtime=0)` 的默认 9 级压缩。这里衡量构建产物和资源请求；未测量安卓真机启动耗时、帧率、内存或功耗。入口仍有 Vite 的大于 500 kB 提示，总安装包体积不等同于首屏资源体积。
