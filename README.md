# 田野来信 · Weather Farm

中文横屏农场经营游戏。参考 Hay Day 的播种、喂养、库存、加工排队、交订单和路边摊循环，代码与场景美术独立原创。农田与牧场采用全屏地图，等级、货币和圆形入口悬浮在边角；田地、牧场、工坊、河塘与小镇通过道路相连。播种、收获、投喂和收取后短暂显示本次实际结果，工坊收取后可手动再做一批。工坊与牧场的待收提示跟随建筑，点击可找到有成品的机器或畜栏。农场门口可接待原创邻居，小镇经营列车访客与店铺。真实天气、本机图文 AI、官方资讯和实际农场记录全部放在独立的“农场助手”界面。

## 农场经营玩法

- **联动动效**：经验环跟随实际等级和经验，等级／金币／钻石只在真实数值变化时滚动；工坊补做成功后按钮收圆、画勾并散开粒子。支持的浏览器从点击处展开页面，助手返回向原入口收回；减少动态效果或不支持转场时直接切页，动效不延迟经营结算。
- **场景与作物细节**：主地图树木、农舍、谷仓、风车、五种动物、六种前期工坊和小镇三座店铺及列车采用原创本地插画，图片加载失败时回退原矢量；河塘、土壤与接地阴影增加层次。麦穗、玉米颗粒和其他作物果实保留矢量细节，成熟地块文字更清楚。动物插画只有整体轻微呼吸；新风车与列车插画为静态。水光和麦田轻微动态支持减少动态效果，整理农场期间暂停。
- **建筑待收提示**：工坊显示已经完成的生产批次数，牧场显示已有产物的畜栏数，提示跟随已保存的建筑位置。点击提示或建筑直接打开首个待收机器的生产队列、或首个待收畜栏；没有待收时仍可打开普通经营页面。它只导航，不自动收取、投喂或扣货；满仓时成品仍显示为待收，实际收取继续检查容量。
- **全屏农场**：农田与牧场不再保留顶部品牌横条、左侧分类栏或底部状态栏。等级与经验在左上，金币与钻石在右上；左下“经营”打开农场菜单，右下“助手”切换独立真实服务。订单、门口来客与镜头入口贴在边缘，中央留给场景与田地。界面参考了 [Hay Day 官方截图的组织方式](docs/hayday-ui-study-v0.12.md)，场景与控件仍为原创。
- **农场菜单**：“经营入口”集中农田、牧场、工坊、订单、探索、小镇、仓库、农场日记八项；“工具与设置”放置农场看板、整理农场、农场手册、检查更新、音效与重新开始。重开先确认；打开菜单不扣货或领奖。工坊、订单等经营页面和真实助手保留各自页面导航。
- **农场门口来客**：点农田左侧的圆形来客头像，或农场日记中的“农场门口来客”，再主动“看看谁来了”。邮差阿穗、竹匠芦叔、邻居陶婶、画师小蓝轮流到访，每次只等一位。这些是本机模拟顾客；一位访客只收购一种已解锁、实际持有的作物、动物产物、加工品、水果或鱼肉，数量 1–5 份，排除建材、工具、饲料、矿石与金属锭。
- **门口交易与等待**：报价为该商品游戏基础总价的 1.1 倍向上取整，另给 2 + 数量的经验；到访后商品、数量和报价固定，作物成交后必须保留至少 2 份种子，不能确认绕过。出售和送客都先确认，提交时重新核对当前访客、库存和时间；送客不扣货也不领奖。成交或送客后等待 2 分钟，再主动接待下一位。稍后再说、关闭窗口或离线会保留来客，不自动交易、失效或领奖。
- **整理农场**：从“农场菜单 → 工具与设置 → 整理农场”进入，选中农舍、工坊或牧场区域后拖动、点选落点或用方向按钮移动；每类区域作为一个整体移动。花坛、树篱、木栅各有 2 件免费摆件，可放置或收起，不扣金币、钻石或库存。地图提示不可放置的格子；耕地、河流、水塘和小镇固定。点“保存布置”才应用草稿，取消不改变当前布置，“恢复初始布置”也先留在草稿中。当前只有一套布局，尚不支持逐台移动 22 类机器或逐块移动田地。
- **农场看板**：点农田/牧场左上等级徽章，或从菜单“工具与设置”打开，查看成熟田地、动物产物、工坊成品、可交订单、路边摊货款和最近完成的倒计时。入口只导航，不自动收取或交货；订单分别核对当前库存，交货后再计算。
- **材料来源**：订单显示明确缺货量，缺货入口和工坊原料可以跳到对应作物、动物、配方、果园、鱼塘、矿山或蜂箱；查看不会扣游戏资源。窄横屏的工坊可切换制作配方和生产队列。
- **操作反馈**：农田与牧场在单次或连续操作成功后，顶部中央短暂显示“本次播种／收获／投喂／收取”，约 2.2 秒消失，新操作替换上一条。按操作前后的真实库存和经验变化汇总，包含消耗、混合作物或产物及实际获得的材料奖励；最多显示 3 项，其余标明项数。跳过、取消、失败或零变更不会新建成功汇总。提示不拦点击、不改变镜头和边角入口，减少动态效果时静态显示后消失。游戏各经营页面继续共享可朗读提示；写盘失败明确标记“未保存”，并提醒导出游戏备份。
- **田地连续操作**：先轻点地块打开操作，再展开“田地工具”，选择浏览、播种、收获；工具默认收起，持续操作方式会保留小入口。选种后划过田地，松手执行一次，经过的地块会预览高亮。资源不足只保留已经完成的部分；多指、失焦、弹窗和切换方式会取消，防止旧点击误操作。
- **新手手册**：可选的六步图鉴串起留种、养殖、工坊、订单、小镇接待和独立农场助手，包含来源导航，不强制阻挡游戏。
- **播种与留种**：12 种作物，每次播种用库存 1 份，成熟收获 2 份和经验；收成进入筒仓，金币来自销售与订单。按倒计时成熟，离线时间继续计算，作物不因天气或未浇水枯萎。
- **牧场连续操作**：先选中畜栏查看操作，再选择浏览、投喂、收集方式；划过畜舍预览，松手后一次执行，每栏只处理一次并使用各自饲料。饲料不足或仓满停止后续操作、保留已完成部分，收集后仍需主动投喂；多指、切页或弹窗会取消尚未执行的手势。就绪畜舍有金色提示，成功后短暂显示收集/投喂反馈。
- **加速确认**：作物和动物加速先确认对象与游戏钻石费用；确认时重新核对批次、计时和库存，已完成或费用变高时阻止误扣，不自动收获、投喂或购买。
- **动物与饲料**：鸡、奶牛、猪、绵羊、山羊；加工对应饲料，投喂后等待鸡蛋、牛奶、培根、羊毛或羊奶。产物进谷仓，再喂下一轮；可以扩建畜舍。
- **加工与队列**：22 类生产建筑、57 个配方；入队时扣原料，机器串行加工，成品等待收取。可以用游戏钻石加速，扩充至 9 个生产位；未开始的任务消耗 1 钻石取消并退回原料。所有钻石动作先显示确认，缺料可直接前往来源。
- **收取后再做一批**：成功收取工坊成品后，队列旁显示刚收取的配方、每批产量和原料的当前库存／所需量，点“再做一批”只手动加入 1 批。原料不足、生产位已满或等级未到时禁用并说明原因；缺料可查看来源，空闲生产位可返回选择配方，满仓成品保留并提供“去仓库”。刚收取记录仅属于本次工坊会话，切换工坊、从来源入口重新定位或离开页面后不保留；不自动补单。所有制作、收取、建造及钻石操作都在提交时使用最新游戏状态重新核对，计时操作使用实际提交时间；钻石报价或对象变化时要求重新确认。
- **订单与销售**：卡车与船订单核对库存后交货，获得金币和经验；路边摊由明确标注的本机 NPC 模拟购买，倒计时结束后收款一次。没有实际支付或真钱收益。
- **仓库与扩建**：谷仓、筒仓分开计容量；满仓阻止收取，成品保留。升级仓库、开放更多田地和畜舍，按等级解锁内容；补给小铺提供基础种子和饲料，经营奖励掉落工具材料。
- **探索**：果园成熟、收果、一次本机照料和砍除；鱼塘钓鱼、消耗工具采矿、蜂箱采蜜及一次性成就奖励，使用明确库存、等级和倒计时。
- **小镇经营**：主动接待模拟列车，每班最多 3 位访客，小镇最多容纳 6 位；乡间杂货铺、林荫咖啡馆、河畔旅舍按需求消耗游戏商品，服务计时完成后手动领取金币、经验与小镇声望。声望解锁设施，再用游戏金币建造；设施最高 3 级，升级增加服务席位。列车冷却、访客、设施和声望纳入游戏存档与备份，不连接真人或邻里站台。
- **镜头与触控**：地图保留完整画布，可拖动查看边缘摆件；单个圆形镜头入口按需展开缩放与复位按钮，支持 100%–180% 缩放、双指缩放、单指拖动和复位，拖动不会误收获；水纹、芦苇与麦田微动支持减少动态效果。
- **存档与备份**：操作后即时保存、退后台保存，保留 v0.1/v0.2/v0.3 存档迁移。农场日记支持游戏进度 JSON 导出及确认恢复，包含农场来客、小镇经营和已保存的农场布置；旧存档或旧备份缺少来客时使用空门口，缺少布局时使用默认布置。损坏存档先保留本机恢复副本。
- **游戏内更新**：从“农场菜单 → 工具与设置 → 检查更新”查看 GitHub 新版本与说明，用户触发下载、查看进度、取消或重试。Android 核对大小、SHA-256、包名、更高版本和相同签名，再打开系统安装器；同一进程重开窗口可以继续安装匹配的已校验包，安装授权返回后会刷新状态；从 v0.4.0 起公开 APK 使用固定签名，见 [更新与签名说明](docs/android-updates.md)。

这是独立单机原型，尚未实现 Hay Day 的全部内容和联机系统。真实邻里、跨玩家交易、德比排行、联网活动、社区小镇、山谷和账号同步需要服务端；系统覆盖与官方参考见 [内容范围表](docs/hayday-feature-scope.md)。没有复制 Hay Day 的地图、角色、音效、图片或客户端源码。

游戏库存、金币、钻石、产量与计时只属于游戏，**不参与真实问诊、实测记录或经营建议**。游戏界面不显示真实天气或 GPS，农场助手不显示游戏钱包。真实服务不受等级或游戏金币限制。重开只清除游戏进度。

## 独立的真实农场助手

农田与牧场点右下“助手”，其他游戏经营页面点顶部“农场助手”，切换到独立界面，使用助手自己的导航打开农场工作台、真实天气、AI 现场观察、农业资讯、市场参考和农事参考六项服务。顶部可返回游戏继续经营；真实资料、待办、实测与问诊案例独立保存，切换界面不会把它们转成游戏数据。

- **天气与检查**：Open-Meteo 区域气温、空气相对湿度、降水、风速和七日预报；显示模型时点、获取时间和缓存状态。高温、低温、降雨和大风触发通用现场检查提醒，可加入真实待办。真实服务不使用游戏库存和产量。
- **选择真实位置**：未设置位置时先提示选择真实农场，不把城市示例或旧缓存当成当地天气；可搜索城市、使用手机定位或手填 WGS84 经纬度，同名城市显示行政区以便区分。Android 定位使用系统 GPS / network provider，不依赖 Google Play，并显示来源与精度，粗定位需确认。所选位置独立保存；切换地区查询失败时不会把旧地区天气显示成新地区结果。
- **本机记录**：农场资料、待办与完成状态、带采样位置/时间/仪器的实测记录；包括空气、土壤与养殖水质。支持 JSON 导出和备份合并。
- **田间问诊**：作物和动物名称不限于游戏品种。输入异常、发生时间、数量、阶段与管理变化，可拍照、录制/选择不超过 30 秒的视频，或使用本机离线中文语音转文字。每次最多三张照片或视频关键帧；原视频动作和声音不参与模型推理。
- **本地 AI**：Android ARM64 原生 llama.cpp + libmtmd CPU 推理，Qwen3.5 图文模型。用户选择下载或导入，按固定版本的大小与 SHA-256 校验；模型就绪后图文推理不联网。JSON 语法约束只保证字段结构，内容还需通过风险与措辞校验。浏览器预览没有该引擎。
- **问诊草稿与恢复**：不完整的表单文字、实测勾选及语音核对状态自动保存到本机，失败时明确提示并可导出草稿。同次运行切页保留临时媒体、说明与完成结果，离开时停止推理/语音；冷启照片需重选或明确选择仅文字。新推理失败/停止后仍保留上份结果；模型出错且仍占内存时可手动卸载再加载，不自动重新分析。
- **问诊备份导入**：单案例、旧版全案例和新版 JSON 备份均先预览，重复跳过、编号冲突保留本机；超过容量或本机资料异常时阻止合并，不静默删减。导入记录标注来源未核验，模型输出从原文重新校验。文字草稿恢复需确认替换，重新选择实测、天气与照片；不改已完成结果、案例或游戏存档。
- **可追溯的问诊记录**：整理观察、可能原因、证据不足、低风险检查及求助条件；独立危险症状规则先提醒。格式错误、用药剂量、确诊和准确率承诺不会变成有效结构化建议。最多保存 20 个本机案例，保留模型版本与耗时；原照片、视频和音轨不写入案例备份。
- **新闻与科普**：读取农业农村部官方列表和原文节选，显示发布日期并链接原文；正文失败不生成摘要。另有标明日期与适用范围的官方季节性指导，以及 FAO、WOAH 等参考资料。
- **经营参考**：农业农村部全国批发均价，保留“元/公斤”、统计范围、报价时点和来源。结合用户核实的当地采购询价、已确认订单及单位成本，提醒交付与销售核查；询价与订单分开，价格上涨不推断需求上涨或自动建议扩产。

## 模型档位与设备

| 模型 | 主模型 + 视觉投影器下载量 | 建议设备内存 | 定位 |
|---|---:|---:|---|
| Qwen3.5 0.8B Q4_K_M | 约 0.74 GB | 6 GB 起 | 轻量兼容；能力有限 |
| Qwen3.5 2B Q4_K_M | 约 1.95 GB | 8 GB 起 | 平衡档 |
| Qwen3.5 4B Q4_K_M | 约 3.41 GB | 12 GB 起 | 高内存可选档，更慢、占用更高 |

首次按设备可见内存推荐档位，用户可以切换。加载时另外检查可用内存；权重之外还需要视觉计算、上下文与系统空间。4B 参数量更大不等于疾病识别准确率已获验证。模型不包含在 APK 中，不会自动下载；首次下载需要网络和足够存储，或分别导入所选档位的主模型和配套 `mmproj-F16.gguf`。应用内提供固定版本来源链接。

安装包仅支持 **ARM64 Android 6.0+**。本机语音需要 **Android 12+、离线语音引擎与已安装的中文语音包**；缺少时明确提示手动输入，不切换云端识别。性能取决于芯片、内存、系统与输入大小；尚未完成安卓真机性能和农学/兽医学专项准确率验证。

## 数据、信息与隐私

- Open-Meteo 是区域气象模型产品，不是农田传感器。空气湿度不能代替根区含水率，空气温度不能代替养殖水温。过时或连接失败的数据保留标识，并暂停新的天气作业提醒。
- 本地模型是通用图文模型，未经该应用的农学和兽医学专项验证，没有经过验证的诊断准确率。输出辅助整理线索和排查，不能替代现场检测、农技人员或执业兽医。
- 模型可能不能按要求输出有效 JSON；应用会保留清楚的失败说明和独立检查提示，不将未验证的模型文字包装成确诊结果。
- 官方全国均价不能代替当地同品种、等级的成交价或消费需求；订单与成本准确性取决于用户输入。不存在自动交易、喷药或设备控制。
- 农场资料、案例、实测和游戏存档保存在本机；关闭 Android 自动备份。主动点击导出会打开系统分享选择器，由用户选择接收位置。清除应用数据或卸载会删除记录，请定期导出。
- 照片/视频在本机缩小、生成预览/关键帧；案例仅保存文字及媒体说明。语音使用 Android 明确的 on-device 识别接口。
- 天气查询会将所选坐标发送给 Open-Meteo；官方资讯/行情及模型下载连接各自公开来源。图文推理不上传农场观察和媒体。无需账号、天气密钥，无广告或后台跟踪。

气象数据：[Open-Meteo](https://open-meteo.com/)（[API](https://open-meteo.com/en/docs)、[使用条款与许可](https://open-meteo.com/en/terms)），按 CC BY 4.0 署名。免费 API 的用途及限额遵循服务条款，商业上线前需选择适用方案。新闻与指导内容引用官方短节选并链接原文，各来源内容遵循原有权利与条款。

## 本地开发与构建

要求 Node.js 22+。

```bash
npm ci
npm run dev
npm test
npm run build
```

网页为开发预览，原生图文 AI、相机和离线语音请使用安卓版本。官方 HTML 在网页预览中可能受跨域限制；原生版通过 Capacitor HTTP 读取，不用虚构资讯替代失败。

安卓构建要求 JDK 21、Android SDK 35 / Build Tools 35.0.0、NDK 28.2.13676358、CMake 3.31.6。首次构建需网络，原生引擎依赖按固定 commit 和源码 SHA-256 下载。

```bash
npm run android:sync
cd android
./gradlew assembleDebug --no-daemon --max-workers=2
```

输出 `android/app/build/outputs/apk/debug/app-debug.apk`，本地开发包使用开发签名。v0.4.0 起公开 APK 另用固定签名，不是应用商店发布包；更早版本签名不同会阻止覆盖，请保留仍需使用的旧版，备份可导出的资料后再决定迁移。GitHub Actions **Build Android APK** 构建并检查，**Publish Android Release** 核对源码、逐项 APK 内容和固定证书后发布 APK、源码 ZIP 与 SHA256SUMS；私钥不上传仓库，具体流程见 [安卓更新说明](docs/android-updates.md)。

## 结构与许可

`src/components/` 为游戏视觉、农场来客、农场布置、游戏小镇与独立农场助手，`src/lib/` 为天气、信息解析、实际记录、问诊校验和游戏规则，`android/app/src/main/java/com/fieldletter/farm/ai/` 与 `src/main/cpp/` 为本机媒体、模型管理与 JNI 推理。`tests/` 包括官方页面快照解析、日期/单位/缓存、位置、订单成本、危险症状、真实记录及玩法检查。本版验证状态见 [v0.14.0 验证范围](docs/validation-v0.14.md)。
